## Final acceptance scope

The source-backed closing audit found no additional concrete client MUST/SHOULD gap in the pinned Tasks, Skills and Events specifications beyond the webhook rotation races subsequently reproduced and fixed. Tasks includes modern/legacy execution, input trust and correlation, cancellation, notifications and same-intent recovery. Skills includes discovery, verified supporting files, URI boundaries, consent and origin-preserving reads across all client surfaces. Events includes poll/push/webhook, controls and cursors, recovery, private durable acceptance, final-settlement disk receipts and operator-owned presentation policy.

The rotation fix publishes pending-key intent before callbacks snapshot state, gates renewal on its persistence and promotes only the key actually sent. Both coordinator-backed regressions failed before the fix and passed afterward; 75 focused checks and typechecking passed. A fresh whole-source verification and independent adjudication remain required before accepting this revision; see the final timestamped manifest rather than inferring acceptance from this paragraph.

Scope limits remain explicit in `COMPLETE.md`: no exactly-once agent effects, no power-loss durability claim, no unattended Tasks enumeration, no automatic prompt-injection immunity, no public webhook deployment and no mandatory implementation of the draft's unresolved optional `v1a` identity mechanism. The declared strict-issuer OAuth conformance exception and macOS-only Linux-keyring skip remain visible. Personal Addy skills are used unchanged; product fixes are not skill revisions.

Method: Personal's Addy `api-and-interface-design` and `test-driven-development` skills, vendored revision `dc27a9c2e13721158157632de61b4106c6c2a2a1`. Define contracts, validate untrusted wire input, demonstrate RED before each implementation slice, and verify public behavior. No skill modifications have been made.

## Events integration decisions to preserve

- One canonical model-facing `mcp_events` interface should coordinate all three modes. Reuse the current push engine and polling loop; do not build a second MCP transport or replace official SDK framing.
- Automatic delivery selection follows the pinned draft: **configured webhook, then push, then poll**. Explicit mode overrides do not silently change modes. Permission/authentication failures are not reasons to downgrade modes.
- An absent cursor is semantically **null**, per the draft. Never retain an older cursor merely because a new frame omits it.
- Accept/deduplicate an event before advancing its recovery cursor; poll page checkpoints follow all page events; push heartbeat checkpoints follow preceding events; webhook HTTP acknowledgement follows acceptance.
- Push callbacks now await durable acceptance before advancing recovery cursors; preserve that ordering when changing the driver.
- Webhook subscription intent and generated secrets must exist before registration/challenge; returned server IDs are routing handles, not authority. Refresh honors granted TTL; stop intent is persisted before remote cleanup. Secrets never enter model tool results or Pi messages.
- Restore only the correct Pi session and configured server context. Exactly-once agent side effects are not a protocol guarantee; retry deduplication and recovery remain required.
- Local HTTPS/CA fixtures with an explicit private-callback allowlist can verify full webhook protocol behavior with a real Pi/Gemini agent without external deployment or disabling TLS verification.
